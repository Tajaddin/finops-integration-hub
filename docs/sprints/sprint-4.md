## Measured

- **Langfuse** (`reports/triage/langfuse-run.json`): 90 challenge-set e-mails sent through n8n to the agent on
  qwen2.5:7b, all 90 accepted and all 90 traced; 1,470 observations; p50 2.68 s, p95 4.20 s per turn; 1.89 LLM
  calls, 1,124 prompt and 116 completion tokens per turn; the model is 97.5% of the latency.
- **Throughput** (`reports/sync/throughput.json`, Odoo with 4 HTTP workers): 3.26 invoices/s with 1 sync worker,
  7.88 with 4, 9.17 with 8; 0 invoices created by the rerun after each. From 4 to 8 workers the gain is small and the
  per-deal p95 rises from 342 ms to 519 ms, consistent with Odoo's 4 HTTP workers being the limit (not profiled).
- **Footprint**: the full stack (20 containers, all profiles) used about 5.9 GiB of RAM while idle after the runs,
  the core profile about 1.5 GiB (`docker stats`).

## What went well

- Alert rules with promtool unit tests turn "would this page at 3 a.m.?" into a test: the restart case (#25) is
  now one, next to the firing and non-firing cases of every rule.
- Generating the dashboard JSON from a script, with a CI drift check, keeps a 13-panel dashboard reviewable in a
  pull request.
- Measuring through Langfuse's own API, not the client's clock, gave numbers anyone with the stack can reproduce
  and showed where the time goes (the model), which settles what to optimise.

## What did not

- **Metrics differed per API worker** (#25): with two uvicorn workers each kept its own registry, so a scrape saw
  one worker's counters. Found while building the dashboard, not by a test.
- **The n8n run-sync webhook returned the e-mail node's output** whenever a sync dead-lettered deals (#26). CI
  missed it because it runs the integration tests before it seeds a book; the local stack, with open dead letters,
  caught it.
- Langfuse v4 has no `/traces` endpoint; the report had to be rebuilt on the Observations API v2, and OpenInference
  records each LLM call twice (`acomplete` wrapping `achat`), so only one of each pair is counted.
- The first Grafana screenshots were blank: the dashboard scrolls inside its own container, so a full-page capture
  is empty. Kiosk mode with a tall viewport fixed it.
- The throughput books are fresh per run, but each later run also re-reads the earlier books' deals (their CRM
  write-backs move them past the cursor), so the 4- and 8-worker runs did slightly more work than the 1-worker run.
